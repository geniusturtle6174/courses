In-class Competition I

Problem Desc

  • (100%) Submit to this kaggle competition: Predicting Airline Satisfaction (Playground Series - Season 6 Episode 10).

Detailed Rules

  • 方法與函式庫限制： Restrictions on methods and libraries:
    • 能 import 的函式庫只有 numpy、sklearn、XGBoost、LightGBM、PyTorch，以及任何 Python 內建之函式庫。此外，必須從頭訓練模型，並以該模型做預測。
    • The only libraries you may import are numpy, sklearn, XGBoost, LightGBM, PyTorch, and any Python built-in libraries. In addition, you must train the model from scratch and use that model to make predictions.
    • 可以使用 optuna 等工具搜尋超參數，但相關動作只能在報告內敘述，而在繳送之程式碼中只能提供搜尋結果。
    • You may use tools such as optuna to search for hyperparameters, but this should only be described in the report, and the submitted code should only include the search result.
    • 若欲使用不在上列中的函式庫，應先取得教師同意。
    • If you wish to use a library not listed above, you must obtain the instructor's approval in advance.
  • 繳送與展示規則： Submission and demonstration rules:
    • 10/29 08:00 前，繳送下列項目至 portal： By 08:00 on 10/29, submit the following items to the portal:
      • 用以達到最佳結果的程式碼：可執行的 *.py files，不要壓縮，不接受其他格式。
      • The code you used to achieve your best result: executable *.py files, not compressed; other formats are not accepted.
      • 報告：檔名為 report.txt，以英文或正體中文撰寫，其中至少應描述你達到最佳成果的做法。
      • A report: filename report.txt, written in English or Traditional Chinese, which should at least describe how you achieved your best result.
      • 你達到的最佳結果：檔名為 score.txt，內容只有一行半形數字，為你在 public LB 上的最佳結果。
      • Your best result: filename score.txt, containing only one line with a single half-width number, which is your best result on the Public LB.
    • 10/30 原上課時間開始後，主動先到教師座位旁排隊等候展示。此外，請於原上課時段準時到場，且於原開始上課時刻起一小時內請勿離場，否則若助教抽驗 Public LB 結果時你恰好因此不在場，則將予扣分。
    • After the original class time begins on 10/30, proactively line up next to the instructor's seat to wait for your demonstration. Also, please arrive on time for the original class period, and do not leave within one hour from the original start time. Otherwise, if the TA happens to do a spot check of your Public LB result while you are away, points will be deducted.

Grading Policy

  • 60% 依據全班之 Public LB 排名給分，40% 依據報告與其他任何要求給分。
  • 60% is based on the ranking of the entire class on the Public LB, and 40% is based on the report and any other requirements.
  • 抽驗發現程式產生出之 submission 與登錄之結果有顯著差距者，亦予扣分。
  • If a spot check reveals a significant discrepancy between the submission produced by your code and your registered result, points will be deducted as well.
  • 遲交但能準時參加 demo 者，分數八折給予；有繳交但未參加展示者，分數折半給予。遲交且未能準時參加 demo 者不給分
  • If you submit late but attend the demo on time, your score will be multiplied by 0.8; if you submit but do not attend the demonstration, your score will be halved. If you submit late and fail to attend the demo on time, you will receive no score.
